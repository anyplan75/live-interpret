# 실시간 통역

여러 교회의 예배를 방송실 PC에서 받아, 고른 언어로 교정·번역하고 성도 자막과 OBS 오버레이로 보냅니다. 음성은 저장하지 않습니다. 언어별 텍스트만 남습니다.

방송실에는 프로그램을 한 번 설치합니다. 성도 자막과 OBS는 링크로 엽니다.

데이터는 기존 Firebase 데이터베이스의 `live-interpret` 경로에만 둡니다. cheil, jifc 경로는 쓰지 않습니다.

## 방송 앱

맥 방송실에서는 Finder에서 `실시간 통역.app`을 더블클릭합니다. 터미널이나 `npm start`는 쓰지 않습니다.

```text
dist/mac-arm64/실시간 통역.app
```

[Releases](https://github.com/anyplan75/live-interpret/releases)의 `live-interpret-버전-mac-arm64.dmg`로 설치할 수도 있습니다. 아직 Apple Developer ID 서명이 없어서 처음 열 때 Finder에서 앱을 Control-클릭 → **열기**를 누릅니다.

처음 실행하면 마이크 권한을 묻습니다. 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 **실시간 통역**을 허용합니다.

입력 목록에는 CoreAudio 장치가 나옵니다. 장치를 고르면 채널이 나타나고, 레벨이 움직이는 채널이 설교 소리입니다. 인식은 그 채널만 사용합니다. 브라우저 기본 마이크는 쓰지 않습니다.

앱을 다시 만들 때는 Node.js 20 이상이 필요합니다.

```bash
npm install
npm run pack:mac
```

### 윈도우 교회 PC

[Releases](https://github.com/anyplan75/live-interpret/releases)에서 `live-interpret-setup-버전-x64.exe`를 받아 실행합니다. 설치 폴더를 고를 수 있고, 바탕화면과 시작 메뉴에 **실시간 통역** 바로가기가 생깁니다. 아직 코드 서명 인증서가 없어서 처음 실행할 때 Windows SmartScreen이 "알 수 없는 게시자"라고 하면 **추가 정보 → 실행**을 누릅니다.

입력 목록에는 WASAPI 장치가 나옵니다. 그 PC에서 ASIO 드라이버를 볼 수 있으면 ASIO도 함께 나옵니다.

설치 파일 없이 소스로 실행할 때는 Node.js 20 이상이 필요합니다. `npm install`이 네이티브 모듈을 받지 못하면 Visual Studio Build Tools가 필요합니다.

```bash
git clone https://github.com/anyplan75/live-interpret.git
cd live-interpret
npm install
npm start
```

### 실행할 때마다 묻는 동의

앱을 켤 때마다 방송 화면보다 먼저 동의 창이 뜹니다. 설교 음성은 저장하지 않고, 그 설교자의 텍스트 교정 내용(말 끊는 위치, 인식 교정, 더 정확한 번역 교정, 더 자연스러운 번역 교정, 용어)을 저장해 다음 설교 번역을 더 자연스럽고 정확하게 만든다는 내용입니다. 저장한 내용은 그 교회 계정과 플랫폼 관리자가 볼 수 있습니다. **동의하고 계속**을 누르면 앱이 열리고, **동의하지 않음 (종료)**를 누르면 앱이 꺼집니다. 동의는 어디에도 기억하지 않으므로 다음 실행 때 다시 묻습니다.

### 설치 파일 만들기와 자동 업데이트

`audify`는 네이티브 모듈이라 설치 파일은 그 운영체제에서만 만듭니다. 맥에서 윈도우용 `audify`를 만들 수 없고, 윈도우에서 맥용을 만들 수도 없습니다. 그래서 GitHub Actions의 `.github/workflows/desktop.yml`이 두 대의 러너에서 따로 빌드합니다.

| 러너 | 결과 |
| --- | --- |
| `macos-14` (Apple Silicon) | `live-interpret-버전-mac-arm64.dmg`, `.zip`, `latest-mac.yml` |
| `windows-latest` | `live-interpret-setup-버전-x64.exe` (NSIS), `latest.yml` |

- PR과 수동 실행(workflow_dispatch)은 빌드만 하고 결과를 Actions 아티팩트로 올립니다.
- `package.json`의 `version`과 같은 태그(예: `v0.2.0`)를 push하면 두 러너가 빌드해서 GitHub Releases의 **초안(draft)** 에 올립니다. 초안을 확인하고 **Publish release**를 눌러야 교회 PC가 업데이트를 받습니다.

```bash
# package.json version 을 0.2.0 으로 올리고 커밋한 뒤
git tag v0.2.0
git push origin v0.2.0
```

자기 PC에서 만들 때는 그 운영체제에서 실행합니다.

```bash
npm run dist:mac   # 맥 (Apple Silicon)
npm run dist:win   # 윈도우 x64
```

앱은 동의 창을 지나면 `electron-updater`로 GitHub Releases의 최신 공개 릴리스를 확인합니다.

- **윈도우**: 새 버전을 뒤에서 내려받고, 앱을 끌 때 설치합니다. 다음 실행부터 새 버전입니다.
- **맥**: 지금은 앱이 임시(ad-hoc) 서명이라 macOS가 스스로 교체를 허락하지 않습니다. 새 버전이 있으면 방송 로그에 알리고 Releases 주소를 보여 줍니다. 맥 자동 설치를 켜려면 나중에 **Apple Developer ID** 인증서로 서명하고 공증(notarize)한 다음 `package.json`의 `liveInterpret.macSilentUpdate`를 `true`로 바꿉니다. 인증서는 저장소에 없고, 받으면 GitHub Secrets(`CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_ID` 등)로 넣습니다.
- 개발 실행(`npm start`)에서는 업데이트를 확인하지 않습니다.

## 두 가지 로그인

로그인은 두 개입니다. 같은 계정을 양쪽에서 쓰지 않습니다.

**전체 관리자**는 이 주소만 사용합니다.

https://anyplan75.github.io/live-interpret/admin.html

관리자는 한 명입니다. 처음 열면 이메일과 비밀번호를 직접 정해서 계정을 만듭니다. 비밀번호는 저장소에 없습니다. 계정이 하나 생긴 뒤에는 새 관리자 가입은 거절되고, 그 계정으로만 관리 페이지에 들어갑니다.

관리 페이지에서만 다룹니다.

- OpenAI 키
- 교회마다 번역 모델
- 예배 용어집
- 교회 이름
- 활성화
- 그 교회의 로그인 이메일과 비밀번호
- 저장된 방송 텍스트와 주보에서 뽑은 내용
- 설교자 프로필 보기

교회를 추가할 때 그 교회의 이메일과 비밀번호도 함께 만듭니다. 계정을 만들어도 관리자 로그인은 빠지지 않습니다. 자막 위치, 글자 크기, 글자색, 주보 업로드, 설교자 등록은 관리 페이지에 없습니다.

**교회 계정**은 방송 앱에서만 사용합니다. 관리자가 그 교회에 만들어 준 이메일과 비밀번호로 로그인합니다. 로그인하면 그 교회만 열리고, 다른 교회를 고르는 목록은 없습니다. 그다음부터는 같은 PC에서 다시 묻지 않습니다.

방송 앱에서만 다룹니다.

- 자막 위치, 글자 크기, 글자색
- 오늘 번역할 언어
- 인식 감도
- 입력 소스와 채널
- 저장 폴더
- 이번 예배 주보 사진
- 그 교회 설교자 등록과 선택
- 방송 시작, 방송 종료

교회 계정은 키를 바꾸지 못합니다. 방송 앱이 관리 페이지에 저장된 키를 읽어 이 PC에 두고 번역합니다. 키 입력칸은 앱에 없습니다. 모델, 용어집, 활성화, 다른 교회의 주보·설교자·자막 모양도 바꾸지 못합니다.

## 방송 순서

1. 방송 앱을 교회 계정으로 한 번 로그인합니다. 그 교회 이름만 표시됩니다.
2. 자막 위치와 글자 크기, 색을 맞춥니다.
3. 이번 주보 사진을 올립니다. 사진은 이 PC에 저장되고, 방송이 시작되면 그 교회 세션에도 파일 이름과 추출한 글이 남습니다. 찬송 번호, 곡 제목, 성경, 설교 제목, 설교자 이름을 인식과 번역에 넣습니다.
4. 설교자를 등록하고 이번 방송의 한 명을 고릅니다. 방송이 끝나면 말투, 교정, 용어, 말 끊는 위치, 정확도 교정, 자연스러움 교정이 그 설교자 프로필에 쌓여 다음 설교에 다시 쓰입니다. 자세한 내용은 아래 [설교자 데이터](#설교자-데이터)에 있습니다.
5. 입력 장치와 채널을 고릅니다.
6. 오늘 번역할 언어를 고릅니다. 한국어는 항상 포함됩니다.
7. 저장 폴더를 고릅니다.
8. 방송 시작을 누릅니다. 비활성 교회는 시작되지 않습니다.

저장 위치는 다음 형태입니다.

```text
선택한 폴더 / 교회 이름 / 2026-09-28_14-05-06 / ko.txt
```

각 언어 파일은 그 언어의 자막 전문입니다. 같은 내용이 클라우드에도 쌓여 관리 화면에서 볼 수 있습니다.

오른쪽 카드에 언어마다 성도 자막 링크와 OBS 링크가 있습니다. 방송 중에 각 언어의 최신 문장을 함께 봅니다.

## 관리 페이지에서 하는 일

성도 자막과 OBS는 로그인 없이 링크로 열립니다. 키, 교회 계정, 모델, 활성화, 용어집, 설교자 프로필, 저장된 방송 텍스트는 관리자로 로그인한 뒤에만 보입니다.

1. 로그인 후 OpenAI 키 칸에 키를 한 번 저장합니다. 키는 페이지 소스, 로그, git에 넣지 않습니다. 방송 앱만 이 키를 읽어 번역하고, 교회 화면에는 보이지 않습니다.
2. 교회 이름과 그 교회의 이메일, 비밀번호를 넣고 추가합니다. 추가된 교회는 활성 상태이고, 기본 자막 모양이 한 번 만들어집니다. 이후 위치와 글자색은 방송 앱에서만 바꿉니다.
3. 교회를 열면 그 교회의 모델을 고치고, 활성화하거나 끌 수 있습니다. 비활성 교회는 방송이 시작되지 않고, 성도 자막과 OBS는 실시간 자막을 열지 않습니다.
4. 교회 계정의 이메일이나 비밀번호를 바꿀 때는 현재 비밀번호를 다시 입력합니다. 이때도 관리자 로그인은 유지됩니다.
5. 성도 홈, 언어별 성도 자막, OBS 주소를 복사해 보냅니다.
6. 방송실에는 송출 앱을 두고, 그 교회의 계정으로 로그인하게 합니다.
7. 방송이 끝나면 같은 교회에서 날짜와 시각을 골라 언어별 텍스트와 주보에서 뽑은 글을 보고 `txt`로 받습니다.
8. 예배 용어집은 교회마다 관리 페이지에서 고칩니다. 교회 이름, 항존직, 이른비, 열방처럼 자주 틀리는 말을 적습니다.
9. 설교자 프로필은 방송 앱이 쌓습니다. 관리 페이지에서 교회를 열면 **설교자 프로필** 칸에 이름, 설교 횟수, 최근 반영 시각, 말투, 교정, 용어, 말 끊는 위치, 정확도 교정, 자연스러움 교정이 보입니다. 보기만 합니다.

## 설교자 데이터

방송을 끝내면 앱이 그 설교자의 데이터에 오늘 배운 것을 더해 `live-interpret/churches/교회아이디/preachers/설교자아이디`에 저장합니다. 음성은 없고 텍스트만 있습니다.

| 칸 | 어디서 오나 | 다음 방송에서 쓰는 곳 |
| --- | --- | --- |
| 말투 `traits` | 방송 뒤 모델 정리 | 인식 프롬프트, 번역 프롬프트 |
| 교정 `corrections` | 인식 문장을 번역기가 고친 것 (`잘못 들은 문장 → 고친 문장`) | 인식 프롬프트, 번역 프롬프트 |
| 용어 `terms` | 방송 뒤 모델 정리 | 인식 키워드, 프롬프트 |
| 말 끊는 위치 `pausePoints` | 인식 조각이 문장 중간에서 끝난 자리. 같은 꼬리가 한 설교에서 두 번 이상이면 남기고, 설교마다 횟수를 더합니다 (`"그래서" 뒤 쉼 7회 — 그래서 / 우리는`) | 그 자리에서 잠깐 쉬어도 문장을 자르지 않고 기다림, 인식·번역 프롬프트 |
| 정확도 교정 `accuracy` | 교정에서 바뀐 낱말(`열반을 → 열방을`)과 방송 뒤 모델이 찾은 오역(`이른비 → early rain (en)`) | 바른 한국어 낱말은 인식 키워드, 번역 프롬프트 |
| 자연스러움 교정 `naturalness` | 방송 뒤 모델이 오늘 번역 예시에서 찾은 어색한 표현 (`Let us do prayer → Let us pray (en)`) | 번역 프롬프트 |

- 같은 줄은 한 번만 남깁니다. 정확도·자연스러움 교정은 같은 원문을 다시 고치면 새 교정이 옛 교정을 대신합니다.
- 칸마다 줄 수와 글자 수 상한이 있어 오래된 항목부터 빠집니다. 말 끊는 위치는 자주 끊는 순서로 남깁니다.
- 설교 횟수는 방송 한 번에 한 번만 올라갑니다.
- 모델 정리가 실패해도(키 없음, 네트워크, 응답 오류) 교정, 말 끊는 위치, 낱말 교정은 그대로 저장합니다.
- 방송 앱에서 설교자 프로필을 저장해도 쌓인 말 끊는 위치와 정확도·자연스러움 교정은 지워지지 않습니다.
- 데이터베이스 규칙상 설교자 데이터는 그 교회 계정만 쓰고, 그 교회 계정과 전체 관리자만 읽습니다. 다른 교회 계정은 읽지도 쓰지도 못합니다.

데이터베이스 규칙 초안은 `firebase/live-interpret.rules.json` 입니다. Firebase 콘솔의 Realtime Database → Rules 에서 기존 규칙의 `live-interpret` 값만 이 내용으로 바꿉니다. `cheil`, `jifc` 와 다른 최상위 경로는 그대로 둡니다. 루트에 `.read: true` 또는 `.write: true` 가 있으면 `live-interpret` 잠금이 적용되지 않으므로, 그 루트 허용은 지우고 다른 최상위 경로의 기존 공개 읽기·쓰기는 각 경로에 남겨 둡니다.

## 성도 자막

관리 페이지의 성도 홈 링크를 엽니다. 오늘 송출하도록 고른 언어만 나옵니다. 언어를 누르면 휴대폰 자막이 열립니다.

직접 여는 주소 형태:

```text
https://anyplan75.github.io/live-interpret/listen.html?church=교회아이디&lang=en
```

글자 크기는 A+ / A- 로 바꿉니다. 말하는 중인 문장은 흐리게, 확정된 문장은 진하게 표시됩니다.

## OBS 오버레이

브라우저 소스에 오버레이 링크를 넣습니다. 배경은 투명입니다. 크기는 예를 들어 1920×1080 으로 둡니다.

```text
https://anyplan75.github.io/live-interpret/overlay.html?church=교회아이디&lang=ko
```

`lang` 값만 바꾸면 언어가 바뀝니다. 위치, 글자 크기, 색은 그 교회 방송 앱에서 저장한 값이 바로 반영됩니다.

## GitHub Pages

공개 주소는 GitHub Pages 입니다. 저장소 Settings → Pages → Branch `main`, folder `/docs` 입니다. 성도 자막, OBS, 관리 페이지가 이 주소로 열립니다. 송출 앱이 복사하는 링크도 이 주소입니다.

Firebase Authentication 에서 이메일/비밀번호 로그인을 켜고, Authorized domains 에 `anyplan75.github.io` 가 있어야 관리 페이지 로그인이 됩니다. 프로젝트는 `live-interpret-db65e` 입니다.
